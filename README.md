# 学员催办工作台

本地单机桌面工具：获取学习数据、保存催办批次、企业微信正式群发、记录反馈、导出全班记录。

## 功能模块

- 顶部「催办工作台」管理催办批次、生成群发名单、反馈录入和批次导出；「群发中心」独立管理名单、参数和发送。
- 顶部「学员画像」显示当前班级完整名单，无需先建立批次，也不按催办条件排除学员。
- 画像填写卡片可收起到右侧，通过竖排「展开学员画像卡片」恢复。点击表头可升降序、搜索多选值（含空白）或按条件筛选，多列条件组合生效；切班清除列筛选。
- 画像「新建名单到群发中心」按当前筛选、排序复制有姓名的真实学员，可配置文字、文件交错的消息。话术支持 `{姓名}`、`{学号}`、`{班期}`、`{状态}`、`{免催日期}`、六个基础画像字段和当前班期全部额外画像字段作为变量，例如 `{所在地区}`。创建时各字段会替换为该学员对应内容并保存进名单。仅创建名单、不发送；不额外套用催办/免催/微信规则，需自行核对筛选范围。同名人员无法唯一定位，创建时会提示，不自动合并。
- 群发中心以「待处理／已发送」消息表格为主：名字、话术1、文件1、话术2等按实际顺序排列。不同人员同一位置的消息类型不一致时列名为「消息N（文字/文件）」。选中消息格后点击「编辑所选消息」，或双击消息格，只修改该格；「编辑此人全部消息」可调整该人的完整消息列表。已发送和待核实记录只读，待核实人员仍显示在待处理页但不会进入发送队列。
- 画像的班期、学号、姓名、状态关联班期学员，只读。六个基础填写字段为微信、QQ、电脑、工具安装、所在地区、学习目的，自动保存。开学时间、军训时间、画像情况迁移为额外字段，与基础字段放在同一个填写面板。
- 「管理字段」按当前班期新增文字、日期、下拉字段；排序与显隐也按班期保存。六个基础字段固定存在，额外字段不再跨班同步。旧版已同步的字段和填写值保留，各班可独立整理。全部班级总览只读，不能管理字段。
- 只有学号、姓名固定显示，其余字段取消勾选后，画像表格、右侧填写和浮窗同步隐藏。额外字段删除仅影响当前班期；基础字段只能隐藏。各班仍使用独立 SQLite 文件，由同一应用管理。
- 画像浮窗对未匹配窗口自动重试，同一联系人定期重新读取资料；也可点击「重试」。切班时清除旧班绑定和锁定，不会把旧班学员带入新班编辑。
- 催办「导出全班 XLSX」先勾选导出字段，按学号升序导出所选批次全班数据，不受当前表格筛选影响。反馈表头为「本次反馈情况（X月X号）」，日期取批次创建日期；单元格仅反馈原文，反馈表不再单独存操作时间。学习看板默认收起。
- 「导出画像」默认导出学号、姓名及六个基础字段，可自行勾选班期、状态、免催日期、额外字段；导出选择不受隐藏列影响。按当前搜索和班级范围导出，保持当前排序，生成 XLSX；每次打开恢复默认八个字段。
- 画像和催办工作台共享「免催日期」，以日历选择、自动保存，可清除。截止当天仍免催，次日恢复；过期日期保留并变灰，不再属于免催范围。表格显示「至X月X号」。
- 勾选「全部班级」可跨班搜索总览，此模式只读；取消勾选后在顶部选班再编辑。不同班级的相同学号独立存储。
- 当前最新批次的姓名、学籍状态、微信随关联资料同步，学习数据、消息原文、发送结果和反馈不重建。新建批次前冻结上一批，历史批次不变。此前明确删除的画像字段不会恢复。
- 顶部「班期学员」从完课平台获取账号可见班期和完整学员名单，按学号补齐缺号。班期和身份信息自动同步到画像及催办名单，不再手动新增班级或导入 Excel。人工资料、反馈和历史快照不被名单同步覆盖。

## 获取班期学员

1. 先在「设置」保存追光鲸鱼账号和密码，再打开「班期学员」选择班期。首次没有缓存时，应用内直接登录并获取。
2. 每个班期的课程和学员名单分别存入数据库。缺少哪部分就自动获取哪部分；已有缓存时切换模块、切换班期、重启软件均不会重复请求。一次成功返回的空名单也会缓存。
3. 课程列表可以展开、选择查看，但不触发学员请求。名单始终使用自动识别的 `01【…】` 或明确标注第 1 节的课程，独立于当前选择；无法唯一识别时提示并保留旧名单，不拿预热课或其他课程代替。
4. 需要更新时只点击「重新获取课程和学员」，刷新班期列表并重新获取当前班期的课程和名单。单页 500 条，不过滤学籍状态，不与作业系统取交集。
5. 表格固定显示「序号、学员学号、学员姓名、状态、类型、昵称」，按学号序号排列，补齐 001 至接口最大序号之间的空缺。缺号沿用前一个学号的 A–E 字母（开头默认 A），补位状态设置为「已退课」，除学号和状态外全部留空（包括序号），导出格式一致。真实学员人数与补位行数分开统计，补位标记仅内部保存，不作为表格列。
   状态和类型使用平台对应的中文标签；昵称取 `nickname`，姓名独立取 `realname`，不使用昵称补充空姓名。旧缓存没有新增三项数据时保持空白，点击一次「重新获取课程和学员」补全，之后继续使用本地缓存。
6. 后续获取到缺号位置的真实学号时自动替换补位。同序号不同字母的真实学员全部保留。不会猜测最大序号以后的空位。
7. 支持搜索与按当前显示导出 XLSX；各班期按 termId 缓存在原主数据库 `term_rosters`、`term_lessons` 表，重启可查看。旧版本已保存名单的班期仅补取课程缓存，不重复获取名单。

网络请求在后台线程执行，单次请求设置超时。接口失败、重复学号、班期不一致、返回数与 total 不符时不更新旧名单；已有名单也不会被一次空响应清空。取消获取后丢弃当前请求的返回结果，不再启动后续步骤。不写入远端平台。补位记录进入画像和全班快照，但不作为发送对象。关闭应用时会等待当前请求结束。

## 启动

```powershell
python -m pip install -r requirements.txt
python main.py
```

数据默认保存在 Windows 当前用户的本地应用数据目录（`LocalTools/学员催办维护名单/followup.db`）。首次启动会自动创建。

## 每日使用

1. 在「班期学员」选择班期并获取名单，自动建立该班画像；已有缓存会在启动时自动同步，无需重新联网。两个模块的班期选择互相对应。
2. 在「设置」分别填写两个平台的账号与原始密码并保存。账号存于本工具数据库，密码存于当前 Windows 用户的凭据管理器，不回显；改账号须重填密码。点击「获取作业班级」，为每个追光鲸鱼班期人工确认作业平台班级和课程。对应关系存于本地数据库；未绑定的班期不允许采集和新建催办。
3. 在「催办工作台」点击「新建催办」，程序先获取最新数据，核对全部在读、非补位学员的两平台数据及姓名后保存快照。有缺失或姓名冲突时暂停建批，原学习数据保留，可查看「采集异常明细」。单独「获取数据」允许保存已取得的单侧数据；缺失一侧显示未获取，数量留空。旧批次不显示获取按钮。
4. 点击「生成群发名单」，按当前筛选结果配置文字、文件消息，或仅生成人员名单后到群发中心补充消息。名单与画像生成方式一致，保留当前排序；不额外套用催办资格规则，不自动发送。
5. 切换「待反馈」，粘贴原文。输入自动存草稿，「记录并下一位」才正式提交。长期忙碌才设置免催日期；今晚／明天补不自动免催。
6. 「批量未回复」仅在本次催办和待反馈中显示，只处理当前筛选可见且没有任何反馈、没有非空草稿的真实学员。反馈登记与发送状态独立，已有内容不会覆盖。
7. 「管理字段」控制表格、详情和催办浮窗的显示及顺序，按班保存；姓名固定显示，学号默认隐藏，不支持增删字段。「导出全班 XLSX」可独立勾选、拖拽字段并记住上次设置，始终导出全班。学习看板仅显示节次、累计完课率、累计作业率和差值。
8. 可打开所选学员的企微联系人，或使用催办浮窗跟随聊天登记反馈、设置免催。浮窗仅匹配当前最新批次，切班或切批次清除原学员绑定。

「全班快照」包含全班所有成员（已完成、未匹配、免催和补位），默认学号升序；「本次催办」仅包含有欠交且符合催办条件的人，默认按欠课数＋欠作业数降序，同数按学号升序。`2/3` 按 5 项排序；手动表头排序仍可使用。切换视图恢复该视图默认排序。历史批次保留当时成员和数据，新成员及补位从新建批次纳入。

## 独立存储与迁移

- `class_roster`：班期学员身份、状态、类型、昵称、补位与当前成员标记。
- `profiles`：仅 `student_id` 和 `fields`；JSON 只保存六个基础画像字段。学号是主键且外键关联 `class_roster`，不重复存姓名、状态。
- `profile_field_definitions` / `profile_field_values`：额外字段定义和填写值，值通过学号与字段 ID 关联。
- `exemptions`：学号和免催日期，画像和工作台共用。旧免催数据首次启动自动迁移；清除后不会从旧字段恢复。
- `reminder_data`：当前完课/作业标记、欠交项目、完成统计、匹配结果及同步时间。
- 各表在每个班的数据库内通过 `student_id` 关联；`students` 仍保留历史兼容结构，但免催判断改用独立的 `exemptions` 表。不同班期仍用各自数据库隔离，原有数据库不合并、不丢弃。
- `campaigns` / `campaign_students`：历史批次及全班快照；反馈继续使用独立关联表，不随获取学习数据改写。
- 旧课程/作业字段迁到 `reminder_data`，允许的人工字段统一名称（包括原来长标题的「画像情况」），删除其余画像字段。按开发阶段要求不新增迁移备份。同步移出的旧学号仅停用当前成员关系；独立反馈与历史批次保留。

## 历史和数据保护

- 「本次催办」视图要求画像的「微信」为「是」；「否」和未填写均排除。当前批次随画像微信修改实时调整，全班快照仍保留所有人；独立名单采用创建时的筛选范围。

- 默认选中当前班最新批次，其身份、状态和微信关联当前资料；以往批次只读，可查看和导出。任何已建立批次的学习快照不被后续获取覆盖。
- 正常执行粘贴和回车后直接显示「已发送」，无需发送后的人工确认，不核验网络送达。结果通过“批次＋学号”回写。异常或中断不能当作已发送，仍保留异常状态防止自动重复发送。
- 本次催办视图排除已完成、有效免催、退课/异动/未加等不符合条件者。当前批次实时判断免催日期，过期或清除后可恢复催办；历史批次保留创建时的免催日期快照，不能修改。独立名单需自行核对筛选范围。
- 正式群发使用本次统一前缀＋姓名，不使用旧版逐人备注覆盖。同名导致联系人重复时阻止启动。
- 未匹配的数据保留原值并提示，导出全班仍包含这些人，使用前应核对提示。
- 已有班继续使用原数据库；新班自动创建同目录 `class_term_<termId>.db`。班期缓存保存在原主数据库，相同学号在不同班不会混用。
- 旧画像和学习反馈仍保留，右侧可展开以往反馈；不相关画像字段不再显示。
- campaigns 保存批次；campaign_students 保存全班快照和发送结果；campaign_feedback 按批次＋学号关联；campaign_drafts 独立存草稿。
- 建议关闭程序后备份整个本地数据目录。

数据获取由 `app/acquisition` 内的采集模块完成，旧的独立采集和登录目录已删除。工具不自动收集聊天反馈、不推断约定时间。发送已整合在 `app/wecom_sender.py`，不执行或依赖 `sent_messages` 下的脚本、话术 CSV、排除名单或 OCR 图片。

## 独立群发中心（v2 快捷键方式，无 OCR）

- 「群发中心」独立于班级和学习数据，关闭重开可选择已保存名单。名单、收件人、发送尝试及参数保存在 `group_messaging.db`。
- 工作台当前入口按筛选结果生成独立名单，与画像入口一致；重复生成属于新名单，需在群发中心核对。历史版本生成的催办来源名单仍保留原资格复核、结果回写及防重复机制。
- 「新建群发」填写名单名称、一行一个姓名（可导入 CSV/TXT），然后配置有序消息字段。每个字段可以是文字或文件，支持上移、下移、删除。普通名单支持 `{姓名}`；画像名单还支持画像字段变量。
- 选择旧名单可「复制批次名单并新建」，人员状态重置为待发送，不复制发送尝试；可选择是否复制消息。复制消息按学号读取当前画像，并从原始模板重新替换变量；学员/变量无法匹配时阻止创建。个人编辑过的内容会一并保留并重新解析。
- 在消息表格上方选择消息列并点击「修改本列」，或点击话术/文件表头，可统一更新该列。保存前显示影响人数与个人改动人数，默认保留个人改动，可勾选覆盖；混合类型列可明确选择统一为文字或文件。「添加消息」追加文字/文件，「调整列」负责移动与删除；移动立即保存，删除需确认。内容编辑窗口中的取消不会保存修改。
- 左侧常驻显示「发送设置」，前缀与参数修改后自动保存；「预览并发送」位于设置标题旁，点击时也会先保存尚未完成的输入。预览时左侧选择联系人，右侧按实际顺序查看每条文字和文件，可用上一人／下一人切换，也可直接返回修改此人消息。预览显示本轮人数、跳过人数及发送模式；修改消息或设置后必须重新预览，只有预览窗口中的开始按钮才会启动处理。
- 所有内容修改仅作用于可继续发送人员；已发送、发送中、结果待确认/仅粘贴人员不可被批量操作覆盖，运行中的批次禁止编辑。编辑后清空旧预览，必须重新预览才能发送；已发送人员要再次发送，请复制为新批次。
- 文件保存绝对路径，不自动复制文件；预览、启动及每人开始前校验文件，预览后文件变化会要求重新预览。
- 默认开启「使用浮窗验证联系人是否存在」。流程与原脚本一致：搜索联系人 → Ctrl+O 打开浮窗核对 → Ctrl+W 关闭浮窗 → 在企业微信主界面按顺序粘贴消息并回车。浮窗不用于发送。关闭该选项则只搜索，不验证浮窗；包含匹配或不验证均有误发风险，发送前提示。
- 默认开启「单条消息模式」(`single_send=True`)：每个文字/文件字段粘贴后发送一次；关闭时全部字段粘贴后统一按一次回车，与原脚本一致。取消回车发送 `confirm_send` 时始终只粘贴，不计为已发送。图片、ZIP 等文件使用原脚本的 Windows 文件剪贴板格式发送。
- 等待设置折叠到「高级参数」，默认采用原脚本值：`wait=0.5`、`timeout=3`、`focus_delay=0.5`、`paste_delay=0.2` 秒；额外联系人间隔默认 0。可一键恢复。参数随名单保存。不使用 OCR。
- 旧测试库 `send_test.db` 和旧发送日志不删除，但旧的虚拟学习数据测试入口已由“自定义名单／测试”替代。

- Windows 上安装依赖并先登录企业微信。按原脚本在主界面发送，发送期间保持空输入框并不要操作电脑。保留窗口焦点/进程检查，但不检查消息是否送达。桌面自动化受客户端界面及快捷键设置影响，首次使用请先用指定测试联系人验证。
- 发送期间不要使用鼠标键盘。全局 **F11** 和界面「暂停」都请求在当前联系人处理完后暂停；只有暂停后再操作电脑。F11 注册失败时不会开始发送。「继续发送」处理剩余名单；「结束本轮」在当前联系人完成后结束。F11 只暂停，不触发继续。
- 发送期间锁定班级/批次切换及新建/获取数据。关闭应用会先请求结束本轮，不直接丢弃正在处理的联系人。
- 每位收件人开始前落库发送尝试，结束后保存结果。催办来源另外记录 `send_attempts`；每次继续或处理下一人均检查当前免催、微信及名单条件。自定义名单不受学员业务条件影响。
- 异常会停止本轮。尚未粘贴消息的错误为「未发送失败」，重新预览后可重试；粘贴后异常或程序中断为「结果待确认」，不会自动重发。到企业微信人工核对后，可在详情中「核实已发送」或「核实未发送」。
- 本次模板只更新尚未发送的内容；已执行/待确认消息原文保留。发送结果写 SQLite，不生成成功/失败 CSV。

采集时作业平台返回的 XLSX 在内存中解析，不自动保存 CSV/XLSX；学习结果写入 SQLite，登录会话缓存保存在应用数据目录。只有手动导出才生成 XLSX 文件。

设置页的「验证登录」使用当前输入的账号密码建立新会话，并读取班期列表检查权限。密码留空时使用该账号在凭据管理器中保存的密码。验证不自动保存账号密码；修改后仍需点击「保存」。
