# 学员催办工作台

本地单机桌面工具：获取学习数据、保存催办批次、企业微信正式群发、记录反馈、导出全班记录。

开发交接：先读 [AGENTS.md](AGENTS.md)、[PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)、[项目策略](docs/agent/policy.md) 和 [ADR 索引](docs/decisions/README.md)；有 Task ID 时直接读对应任务，否则查 [活动任务](docs/tasks/README.md)。按需查阅 [架构说明](docs/architecture.md)、[工作协议](docs/agent/workflow.md)；Git 写操作前读 [Git 协议](docs/agent/git.md)。无需一次读取全部文档。

## 功能模块

- 左侧导航切换八个业务模块，「学习概览」位于工作台之后，「群发中心」位于最后。班期学员、画像、催办、概览、备注与直播提醒共用顶部班期下拉框，保留「调试重启」。启动窗口为屏幕可用区域的90%。「催办工作台」管理催办批次、名单、逐人欠交与反馈；「学习概览」负责学习图表、历史对比和目标试算；「群发中心」独立管理名单、参数和发送。
- 「学员画像」显示当前班级完整名单，无需先建立批次，也不按催办条件排除学员。工作台窄窗口通过「学员详情／学员列表」切换；画像通过「查看画像／收起画像」切换，宽窗口保留左右分栏。
- 画像填写卡片可收起到右侧，通过竖排「展开学员画像卡片」恢复。点击表头可升降序、搜索多选值（含空白）或按条件筛选，多列条件组合生效；切班清除列筛选。筛选结果会冻结：改字段、登记反馈、免催、发送回写以及切换模块都不会把学员移出表格，只把该行标为“已不符合当前筛选”（淡橙色），需要点「重新应用筛选」、改搜索/视图/列筛选或清除筛选才更新；「重新应用筛选」只在出现过期行时显示。工具条会显示“正在处理 第 i / n 条 · 姓名”作为处理进度；重新筛选时若正在处理的人被筛掉，高光自动落到原顺序中的下一条，不会跳回队首。名单生成与导出画像只包含真正匹配筛选的人，未匹配的过期行不计入。
- 画像「生成群发名单」按当前筛选、排序复制有姓名的真实学员，可配置文字、文件交错的消息。话术支持 `{姓名}`、`{学号}`、`{班期}`、`{状态}`、`{免催日期}`、六个基础画像字段和当前班期全部额外画像字段作为变量，例如 `{所在地区}`。创建时各字段会替换为该学员对应内容并保存进名单。仅创建名单、不发送；不额外套用催办/免催/微信规则，需自行核对筛选范围。同名人员无法唯一定位，创建时会提示，不自动合并。
- 画像操作区按「人数与搜索 → 生成群发名单／管理字段／聊天跟随浮窗 → 范围与筛选」排列。催办顶部操作依次排列批次选择（280px，展开列表同宽）、刷新数据、新建催办、导出全班 XLSX；列表操作区依次排列视图选择、生成群发名单、管理字段、聊天跟随浮窗与收窄的搜索框，窄窗口自动换行。画像填写下拉选项中的「未填写（清空）」统一放在末尾，主卡片与浮窗一致。填写卡片的姓名右侧可「打开企微联系人」，「选项」展开前缀输入及使用前缀、验证联系人、保留浮窗三个勾选项。设置页「企微联系人」可保存默认前缀；已有班期记住的前缀优先（包括空值），未配置班期使用默认值，也可在卡片选项中改用默认值。
- 群发中心以「待处理／已发送」消息表格为主：名字、话术1、文件1、话术2等按实际顺序排列。不同人员同一位置的消息类型不一致时列名为「消息N（文字/文件）」。选中消息格后点击「编辑所选消息」，或双击消息格，只修改该格；「编辑此人全部消息」可调整该人的完整消息列表。已发送和待核实记录只读，待核实人员仍显示在待处理页但不会进入发送队列。
- 画像的班期、学号、姓名、状态关联班期学员，只读。六个基础填写字段为微信、QQ、电脑、工具安装、所在地区、学习目的，自动保存。开学时间、军训时间、画像情况迁移为额外字段，与基础字段放在同一个填写面板。
- 「管理字段」按当前班期新增文字、日期、下拉字段；排序与显隐也按班期保存。六个基础字段固定存在，额外字段不再跨班同步。旧版已同步的字段和填写值保留，各班可独立整理。全部班级总览只读，不能管理字段。
- 只有学号、姓名固定显示，其余字段取消勾选后，画像表格、右侧填写和浮窗同步隐藏。额外字段删除仅影响当前班期；基础字段只能隐藏。各班仍使用独立 SQLite 文件，由同一应用管理。
- 画像浮窗对未匹配窗口自动重试，同一联系人定期重新读取资料；也可点击「重试」。切班时清除旧班绑定，不会把旧班学员带入新班编辑。浮窗保留「置顶」与「重试」，文本及下拉选择在短暂停顿后自动保存，切换或关闭前会提交待保存内容。
- 催办「导出全班 XLSX」可勾选字段，按学号升序导出所选批次全班，不受筛选影响。反馈表头日期取批次时间，单元格仅反馈原文。
- 「学习概览」四页签：最新数据固定实际最新批次；历史批次独立单批；批次对比独立选择两批及共同评估节次；目标追踪独立选择批次、累计节次及目标。概览操作不切换工作台正在处理的批次/学员。「重读快照」仅读本地，学习采集仍在工作台。切班重置选择。
- 统计范围为本批全班在读非补位，包含免催、无微信与已完成者。累计率＝第1～N节全部完成人数÷在读人数，差值＝累计完课率－累计作业率；≤5pp优秀、≤10pp良好、≤15pp及格、>15pp不合格。两批曲线以实线/虚线及批次图例区分，滑块调整范围，悬浮/点击或左右键、回车查看同节次明细。旧单节/缺快照/分母不一致降级留空，缺失不估算；两批分母不同明确提示，变化不代表催办因果效果。
- 完课次数人数为恰好k节，比例以全班在读人数为分母，完课率/人数为完成不少于k节的比例/人数。未知完成计数不归入0次；可跟进按该桶本批人工标记是者，各行独立，历史也可补标记。覆盖列出已填写/是/否/未填写；整批未填写为—，全否为0。「完成人数」「本周是否有退课」无数据源，保持空单元格。目标85%仅为试算示例，输入0～100%；差值目标15/10/5pp，假设完课人数不变并通过补齐作业降差值。目标不保存；固定节次观察截至评估批次最近至多5批，缺失点留空。
- 「导出画像」默认导出学号、姓名及六个基础字段，可自行勾选班期、状态、免催日期、额外字段；导出选择不受隐藏列影响。按当前搜索和班级范围导出，保持当前排序，生成 XLSX；每次打开恢复默认八个字段。
- 画像和催办工作台共享「免催日期」，以日历选择、自动保存，可清除。截止当天仍免催，次日恢复；过期日期保留并变灰，不再属于免催范围。表格显示「至X月X号」。
- 勾选「全部班级」可跨班搜索总览，此模式只读；取消勾选后在顶部选班再编辑。不同班级的相同学号独立存储。
- 当前最新批次的姓名、学籍状态、微信随关联资料同步，学习数据、消息原文、发送结果和反馈不重建。新建批次前冻结上一批，历史批次不变。此前明确删除的画像字段不会恢复。
- 顶部「班期学员」从完课平台获取账号可见班期和完整学员名单，按学号补齐缺号。班期和身份信息自动同步到画像及催办名单，不再手动新增班级或导入 Excel。人工资料、反馈和历史快照不被名单同步覆盖。
- 顶部「备注批改」按画像「微信=是」批量把企业微信备注改成「前缀＋姓名」（如 `py175示例学员`）。
- 顶部「未进直播间」按节次读取平台「直播观看时长」，把没有观看记录的学员筛成名单，送到群发中心通知上课。

## 获取班期学员

1. 先在「设置」保存追光鲸鱼账号和密码，再打开「班期学员」选择班期。首次没有缓存时，应用内直接登录并获取。
2. 每个班期的课程和学员名单分别存入数据库。缺少哪部分就自动获取哪部分；已有缓存时切换模块、切换班期、重启软件均不会重复请求。一次成功返回的空名单也会缓存。
3. 课程列表可以展开、选择查看，但不触发学员请求。名单始终使用自动识别的 `01【…】` 或明确标注第 1 节的课程，独立于当前选择；无法唯一识别时提示并保留旧名单，不拿预热课或其他课程代替。
4. 需要更新时只点击「重新获取课程和学员」，刷新班期列表并重新获取当前班期的课程和名单。单页 500 条，不过滤学籍状态，不与作业系统取交集。
5. 表格固定显示「序号、学员学号、学员姓名、状态、类型、昵称」，按学号序号排列，补齐 001 至接口最大序号之间的空缺。缺号沿用前一个学号的 A–E 字母（开头默认 A），补位状态设置为「已退课」，除学号和状态外全部留空（包括序号），导出格式一致。真实学员人数与补位行数分开统计，补位标记仅内部保存，不作为表格列。
   状态和类型使用平台对应的中文标签；昵称取 `nickname`，姓名独立取 `realname`，不使用昵称补充空姓名。旧缓存没有新增三项数据时保持空白，点击一次「重新获取课程和学员」补全，之后继续使用本地缓存。
6. 后续获取到缺号位置的真实学号时自动替换补位。同序号不同字母的真实学员全部保留。不会猜测最大序号以后的空位。
7. 支持搜索与按当前显示导出 XLSX；各班期按 termId 缓存在原主数据库 `term_rosters`、`term_lessons` 表，重启可查看。旧版本已保存名单的班期仅补取课程缓存，不重复获取名单。

网络请求在后台线程执行，单次请求设置超时。接口失败、重复学号、班期不一致、返回数与 total 不符时不更新旧名单；已有名单也不会被一次空响应清空。取消获取后丢弃当前请求的返回结果，不再启动后续步骤。不写入远端平台。补位记录进入画像和全班快照，但不作为发送对象。关闭应用时会等待当前请求结束。

## 启动

```powershell
python -m pip install -r requirements.txt
python main.py
```

数据默认保存在 Windows 当前用户的本地应用数据目录（`LocalTools/学员催办维护名单/followup.db`）。首次启动会自动创建。

调试时先保存代码，再点击顶部「调试重启」。独立助手会等待原进程退出，用当前 Python 环境重新启动并重新加载 Python/QML 代码。采集、账号验证、发送或打开联系人期间按钮暂不可用；退出仍走原有保存和关闭流程。新进程独立运行，不自动重新连接 VS Code 调试器。入口在 `app/restart.py`，进程等待与启动在不依赖业务模块的 `app/restart_helper.py`。

重启后的进程输出保存在 `%TEMP%/student-management-restart.log`（下次重启覆盖）；Python 启动异常会显示错误提示。

## 每日使用

1. 在「班期学员」选择班期并获取名单，自动建立该班画像；已有缓存会在启动时自动同步，无需重新联网。两个模块的班期选择互相对应。
2. 在「设置」分别填写两个平台的账号与原始密码并保存，两个平台的账号卡片并排显示（窗口较窄时自动上下排列），整页支持滚轮和滚动条。账号存于本工具数据库，密码存于当前 Windows 用户的凭据管理器，不回显；改账号须重填密码。点击「获取作业班级」，为每个追光鲸鱼班期人工确认作业平台班级；课程按平台该班级的主课程自动对应，无需单独选择（平台返回多个课程时才需要选择）。获取到的作业班级目录和对应关系都存于本地数据库，重启后直接带出，不必重新获取；未绑定的班期不允许采集和新建催办。
3. 在「催办工作台」点击「新建催办」，程序先获取最新数据，核对全部在读、非补位学员的两平台数据及姓名后保存快照。有缺失或姓名冲突时暂停建批，原学习数据保留，可查看「采集异常明细」。「刷新数据」位于「新建催办」左侧，点击后重新采集；单独刷新允许保存已取得的单侧数据，缺失一侧显示未获取，数量留空。最新批次的学习列、看板和批次时间（批次下拉、反馈列日期）都会跟随每次刷新更新，本次未返回的学员保留原数据；旧批次保持当时快照与时间，也不显示「刷新数据」。
4. 点击「生成群发名单」，按当前筛选结果配置文字、文件消息，或仅生成人员名单后到群发中心补充消息。名单与画像生成方式一致，保留当前排序；不额外套用催办资格规则，不自动发送。
5. 视图保留「全班快照」「本次催办」；查找未填写反馈者时，在「本次催办」中对「本次反馈情况」列筛选「为空」。反馈使用单行输入框，点击输入框展开快捷列表，可选「答应补课」「未接听电话」等内容追加到反馈末尾，已有内容时以「；」分隔；直接键入时列表收起，支持自由填写。列表在输入框上方或下方展开，不覆盖输入框；底部「添加选项…」新增快捷内容，按班期记住，主卡片和催办浮窗共用。停止输入约半秒或离开输入框时自动保存，可随时修改。非空内容计为已回复，清空恢复待反馈；保存不推进选择，该行仍留在冻结筛选中并标记为已不符合当前筛选。切换学员、班期、批次或关闭前提交待保存内容。历史批次只读。旧反馈与旧草稿完整加载，编辑后保存为本批次的一份反馈。长期忙碌才设置免催日期；今晚／明天补不自动免催。
6. 「批量未回复」仅在本次催办中显示，只处理当前筛选可见且没有任何反馈、没有非空草稿的真实学员。反馈登记与发送状态独立，已有内容不会覆盖。
7. 「管理字段」控制表格、详情和催办浮窗的显示及顺序，按班保存；姓名固定显示，学号默认隐藏，不支持增删字段。「导出全班 XLSX」可独立勾选、拖拽字段并记住上次设置，始终导出全班。进入「学习概览」查看最新、历史、双批对比或目标追踪；完课次数的已知桶人数加未知计数人数等于本批全班在读人数。
8. 可打开所选学员的企微联系人，或使用催办浮窗跟随聊天登记反馈、设置免催。浮窗仅匹配当前最新批次，切班或切批次清除原学员绑定。

「全班快照」包含全班所有成员（已完成、未匹配、免催和补位），默认学号升序；「本次催办」仅包含有欠交且符合催办条件的人，默认按欠课数＋欠作业数降序，同数按学号升序。`2/3` 按 5 项排序；手动表头排序仍可使用。切换视图恢复该视图默认排序。历史批次保留当时成员、数据和批次时间；最新批次的学习数据与批次时间随「刷新数据」更新，但成员（含新成员及补位）只在新建批次时变动。

## 独立存储与迁移

- `class_roster`：班期学员身份、状态、类型、昵称、补位与当前成员标记。
- `profiles`：仅 `student_id` 和 `fields`；JSON 只保存六个基础画像字段。学号是主键且外键关联 `class_roster`，不重复存姓名、状态。
- `profile_field_definitions` / `profile_field_values`：额外字段定义和填写值，值通过学号与字段 ID 关联。
- `exemptions`：学号和免催日期，画像和工作台共用。旧免催数据首次启动自动迁移；清除后不会从旧字段恢复。
- `reminder_data`：当前完课/作业标记、欠交项目、完成统计、匹配结果及同步时间。
- 各表在每个班的数据库内通过 `student_id` 关联；`students` 仍保留历史兼容结构，但免催判断改用独立的 `exemptions` 表。不同班期仍用各自数据库隔离，原有数据库不合并、不丢弃。
- `campaigns` / `campaign_students`：历史批次及全班快照；反馈继续使用独立关联表，不随获取学习数据改写。
- 旧课程/作业字段迁到 `reminder_data`，允许的人工字段统一名称（包括原来长标题的「画像情况」），删除其余画像字段。按开发阶段要求不新增迁移备份。同步移出的旧学号仅停用当前成员关系；独立反馈与历史批次保留。

## 历史和数据保护

- 「本次催办」视图要求画像的「微信」为「是」；「否」和未填写均排除。当前批次随画像微信修改实时调整，全班快照仍保留所有人；独立名单采用创建时的筛选范围。

- 默认选中当前班最新批次，其身份、状态和微信关联当前资料；以往批次只读，可查看和导出。任何已建立批次的学习快照不被后续获取覆盖。
- 正常执行粘贴和回车后直接显示「已发送」，无需发送后的人工确认，不核验网络送达。结果保存在群发名单；旧催办来源名单另通过“批次＋学号”回写。异常或中断不能当作已发送，仍保留异常状态防止自动重复发送。
- 本次催办视图排除已完成、有效免催、退课/异动/未加等不符合条件者。当前批次实时判断免催日期，过期或清除后可恢复催办；历史批次保留创建时的免催日期快照，不能修改。独立名单需自行核对筛选范围。
- 正式群发使用本次统一前缀＋姓名，不使用旧版逐人备注覆盖。同名导致联系人重复时阻止启动。
- 未匹配的数据保留原值并提示，导出全班仍包含这些人，使用前应核对提示。
- 已有班继续使用原数据库；新班自动创建同目录 `class_term_<termId>.db`。班期缓存保存在原主数据库，相同学号在不同班不会混用。
- 旧画像和学习反馈仍保留，右侧可展开以往反馈；不相关画像字段不再显示。
- campaigns 保存批次；campaign_students 保存全班快照和发送结果；campaign_feedback 按批次＋学号关联；campaign_drafts 独立存草稿。
- 建议关闭程序后备份整个本地数据目录。

数据获取由 `app/acquisition` 内的采集模块完成。工具不自动收集聊天反馈、不推断约定时间。发送已整合在 `app/wecom_sender.py`，不执行或依赖 `sent_messages` 下的脚本、话术 CSV、排除名单或 OCR 图片。

## 独立群发中心（v2 快捷键方式，无 OCR）

- 「群发中心」独立于班级和学习数据，关闭重开可选择已保存名单。名单、收件人、发送尝试及参数保存在 `group_messaging.db`。
- 工作台当前入口按筛选结果生成独立名单，与画像入口一致；重复生成属于新名单，需在群发中心核对。历史版本生成的催办来源名单仍保留原资格复核、结果回写及防重复机制。
- 「新建群发」填写名单名称、一行一个姓名（可导入 CSV/TXT），然后配置有序消息字段。每个字段可以是文字或文件，支持上移、下移、删除。普通名单支持 `{姓名}`；画像名单还支持画像字段变量。
- 选择旧名单可「复制批次名单并新建」，人员状态重置为待发送，不复制发送尝试；可选择是否复制消息。复制消息按学号读取当前画像，并从原始模板重新替换变量；学员/变量无法匹配时阻止创建。个人编辑过的内容会一并保留并重新解析。
- 在消息表格上方选择消息列并点击「修改本列」，或点击话术/文件表头，可统一更新该列。保存前显示影响人数与个人改动人数，默认保留个人改动，可勾选覆盖；混合类型列可明确选择统一为文字或文件。「添加消息」追加文字/文件，「调整列」负责移动与删除；移动立即保存，删除需确认。内容编辑窗口中的取消不会保存修改。
- 左侧常驻显示「发送设置」，前缀与参数修改后自动保存；「预览并发送」位于设置标题旁，点击时也会先保存尚未完成的输入。预览时左侧选择联系人，右侧按实际顺序查看每条文字和文件，可用上一人／下一人切换，也可直接返回修改此人消息。预览显示本轮人数、跳过人数及发送模式；修改消息或设置后必须重新预览，只有预览窗口中的开始按钮才会启动处理。联系人前缀为空时，点击「预览并发送」会先弹窗提醒（将直接用姓名作为备注，可能匹配到错误的人）：只提醒、不强制填写，可返回补充前缀，也可继续预览逐人核对。
- 所有内容修改仅作用于可继续发送人员；已发送、发送中、结果待确认/仅粘贴人员不可被批量操作覆盖，运行中的批次禁止编辑。编辑后清空旧预览，必须重新预览才能发送；已发送人员要再次发送，请复制为新批次。
- 文件保存绝对路径，不自动复制文件；预览、启动及每人开始前校验文件，预览后文件变化会要求重新预览。
- 默认开启「使用浮窗验证联系人是否存在」。流程与原脚本一致：搜索联系人 → Ctrl+O 打开浮窗核对 → Ctrl+W 关闭浮窗 → 在企业微信主界面按顺序粘贴消息并回车。浮窗不用于发送。关闭该选项则只搜索，不验证浮窗；包含匹配或不验证均有误发风险，发送前提示。
- 默认开启「每条消息单独发送」(`single_send=True`)：每条文字/文件消息粘贴后各发送一次；关闭时全部消息粘贴后统一按一次回车，与原脚本一致。该选项位于「粘贴后回车发送」下方；未勾选回车发送 `confirm_send` 时该选项禁用、只粘贴不发送，也不计为已发送。图片、ZIP 等文件使用原脚本的 Windows 文件剪贴板格式发送。
- 等待设置折叠到「高级参数」，默认采用原脚本值：`wait=0.5`、`timeout=3`、`focus_delay=0.5`、`paste_delay=0.2` 秒；额外联系人间隔默认 0。可一键恢复。参数随名单保存。不使用 OCR。
- 旧测试库 `send_test.db` 和旧发送日志不删除，但旧的虚拟学习数据测试入口已由“自定义名单／测试”替代。

- Windows 上安装依赖并先登录企业微信。按原脚本在主界面发送，发送期间保持空输入框并不要操作电脑。保留窗口焦点/进程检查，但不检查消息是否送达。桌面自动化受客户端界面及快捷键设置影响，首次使用请先用指定测试联系人验证。
- 发送期间不要使用鼠标键盘。全局 **F11** 和界面「暂停」都请求在当前联系人处理完后暂停；只有暂停后再操作电脑。F11 注册失败时不会开始发送。「继续发送」处理剩余名单；「结束本轮」在当前联系人完成后结束。F11 只暂停，不触发继续。
- 发送期间锁定班级/批次切换及新建/刷新数据。关闭应用会先请求结束本轮，不直接丢弃正在处理的联系人。
- 每位收件人开始前落库发送尝试，结束后保存结果。催办来源另外记录 `send_attempts`；每次继续或处理下一人均检查当前免催、微信及名单条件。自定义名单不受学员业务条件影响。
- 单个联系人发送失败不会中止本轮：未粘贴消息的错误记为「未发送失败」，留在待处理并继续下一位，重新预览后可重试；粘贴后异常或程序中断记为「结果待确认」，不会自动重发，需到企业微信人工核对后在详情中「核实已发送」或「核实未发送」。工作台旧催办发送接口（`Workflow.sender`，当前界面无入口）仍保持异常即停止本轮。
- 本次模板只更新尚未发送的内容；已执行/待确认消息原文保留。发送结果写 SQLite，不生成成功/失败 CSV。

## 备注批改

在企业微信主界面上把学员备注从旧格式（`姓名/新生`）批量改为新格式（`前缀＋姓名`，如 `py175示例学员`）。

- 名单只取当前班期画像中「微信=是」的学员，学号/姓名来自班期学员；重名者只标注「存在重名」，不阻断。
- 前缀默认按当前班期推导（`P2026175` → `py175`），可以手动修改，按班期保存；推导不出时留空并提示手填。
- 每位学员的处理链：用**姓名**搜索 → `Ctrl+O` 打开联系人浮窗 → 读取浮窗标题作为真实备注 → 关闭浮窗并确认回到主窗口。判定规则：

  | 浮窗标题 | 判定 | 动作 |
  | --- | --- | --- |
  | 含「前缀＋姓名」 | 已符合 | 跳过改名，仅写回数据库 |
  | `姓名/xxx`（姓名开头且含 `/`） | 旧格式 | 改名为「前缀＋姓名」 |
  | 其它 | 待确认 | 只记录，不改；可选中后「强改选中项」 |
  | 标题不含该姓名 | 未找到 | 只记录，本轮继续下一位 |

- 真实备注与批改状态分别写入本班的 `student_contacts`（学号 → 企微真实备注名）与 `wecom_remark_scan`（浮窗备注、目标备注、状态、说明、时间），所以已改好的学员重启后仍会跳过。改好后只要把群发中心的联系人前缀填成同一前缀，群发搜索就能直接命中。
- 备注修改由 `app/wecom_remark.py` 的 `change_wecom_remark` 完成（OCR 定位，保存前后双重核验），过程截图保存在项目下的 `wecom_remark_evidence/`；页面提供「打开留证截图目录」。
- 编辑流程：点击聊天顶部备注名 → 点击描述 → 核验备注名输入框的原值 → 直接修改。点击描述后利用输入框已有焦点，不再额外点击输入框；保存前后仍核验备注。
- 单人失败不中止本轮，失败与未找到的记录可「重试未找到／失败」；「标记跳过所选」的状态在重跑时不再处理。
- 全局 **F11** 与「暂停」都在**当前联系人处理完成后**暂停，不打断正在进行的 OCR 与按键序列；暂停后可操作电脑，「继续」处理剩余名单。处理期间不要操作鼠标键盘。

采集时作业平台返回的 XLSX 在内存中解析，不自动保存 CSV/XLSX；学习结果写入 SQLite，登录会话缓存保存在应用数据目录。只有手动导出才生成 XLSX 文件。

## 未进直播间

按节次找出这节课还没进入直播间的学员，生成群发名单提醒上课。

- 数据来自班期学员直播数据接口的 `hisLearningTime`（平台页面上叫「直播观看时长」，单位秒），**按节次独立**：一节一个值，与「累计观看时长」「回放观看时长」不是同一个字段。
- 判定：该字段为 `null` 表示这节课**没有任何观看记录**，即没有进入过直播间。`0 秒` 是「有记录但时长为 0」，默认仍算已进入；勾选「把直播观看 0 秒也算作未进入」才会把它们加进名单。汇总行始终分开显示未进入、已进入与 0 秒的计数。
- 名单范围：平台**在读** ＋ 画像**微信=是** ＋ 当前**不在免催期**的学员。补位、接口没返回姓名、画像没有微信、正在免催的人都只计数不入选；接口返回但不在本班名单的人会提示「名单可能落后」，可到「班期学员」重新获取。
- 操作顺序：选班次（页面顶部班级切换器）→ 选节次 →「获取未进直播间名单」。节次取自「班期学员」缓存的课程列表，本页「刷新课程」只更新缓存，不改变「班期学员」页第 1 节的默认值；获取失败或取消不覆盖上次结果，切班或换节次立即作废上一节的数据。
- 每节课只提醒一次：点「生成群发名单」并成功创建名单后，本班会记下这些人的「本节已提醒」标记。已提醒的学员仍显示在表格里（标「已提醒 时间」），默认不再进入新名单；取消勾选「排除本节已提醒的学员」可强制重发，或点「清除本节提醒记录」整节重来。
- 「生成群发名单」复用画像相同的对话框：名单名称、多条文字或文件、变量 `{姓名}`、`{学号}`、`{班期}`、`{状态}`、`{课程}`、`{直播观看时长}`。**只创建名单，不会自动发送**；联系人前缀由群发中心参数区填写（与备注批改的前缀一致才能搜到人）。名单内重名会按既有规则被拦截。
- 「显示本节全部学员」可把已进入的人一并列出核对；本模块不导出 XLSX。

设置页的「验证登录」使用当前输入的账号密码建立新会话，并读取班期列表检查权限。密码留空时使用该账号在凭据管理器中保存的密码。验证不自动保存账号密码；修改后仍需点击「保存」。

作业班级目录按作业平台账号缓存在本工具数据库中，换账号后不会沿用上一个账号的班级目录，重新「获取作业班级」即可。
