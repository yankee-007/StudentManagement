# Git 工作与交付协议

Git 本地版本控制与可选远端服务解耦。操作遵循 [项目策略](policy.md)，不把本协议当作所有外部操作的自动授权。

先应用有效策略：Git 写入关闭时不初始化/暂存/提交/推送；自动提交关闭时恢复提交不能绕过，ask 需要适用授权；远端或推送关闭时不自动上传。保留许可的文件成果并报告恢复限制，不为得到 checkpoint 放宽配置。

## 基线与修改归属

Git 写操作前确认项目根、当前分支或 detached 状态、HEAD 或 unborn 状态、staged/unstaged/untracked 内容及进行中的 Git 操作。

保护现有修改；不擅自 reset、clean、stash、取消暂存、覆盖文件或接管未完成的 merge/rebase。检测到意外变更时重新核对归属，不把它们自动认领为当前任务。

同文件可能混有用户修改。按具体文件或修改块暂存前核对来源，提交前复核整个 staged 快照。无法可靠分离时暂停自动提交并说明，不使用 `git add .` 掩盖范围判断，也不把用户 staged 内容顺带提交。

## Commit 与恢复

按逻辑工作单元提交，不强行将一个 Feature 压成一个 commit，也不机械拆开本应一起验证的代码和测试。沿用项目消息格式，可在正文加入 `Task: TASK-...` 建立关联。

使用真实身份与既有签名约定；缺失时询问必要信息，不伪造姓名/邮箱、不改全局身份。遇到 hook、签名或检查失败，修复相关问题或报告，不能静默绕过。

普通提交满足该工作单元的验证要求。恢复提交可保存未完成代码，但要标明完成范围、失败/未运行检查与下一步，并满足当前分支约定。恢复提交不代表人工验收、可发布状态或推送授权。

提交前检查文档影响、差异、路径范围和敏感内容；提交后核验结果，保留任何仍未提交的工作并说明。

## Secret 与上传范围

commit 前检查完整 staged 内容；push 前检查此次新暴露给目标的提交与内容，首次上传可能覆盖全部待上传历史。仅检查当前 diff 不足以排除早期提交中的秘密。

范围限于相关仓库和待发送内容，不扫描整个磁盘、无关个人数据或大型数据库。先按文件与类型识别风险，再必要地检查内容，输出只报告位置和类型，不回显凭据值。

检查 `.env`、凭据配置、私钥、token、Cookie、任务文本和相关附件；记录检查范围及无法覆盖的二进制/LFS 等内容。规则扫描不能证明不存在所有秘密。发现问题阻止受影响的提交/上传；不自动改写历史或轮换凭据。

`.gitignore` 不取消已跟踪内容；添加忽略规则不能替代泄漏处置。

## Push

需同时满足：上传范围已获授权且仍适用于当前任务/阶段、实际目标匹配、分支允许、提交内容明确、所需验证与验收条件满足。存在 remote、登录成功或仓库私有，都不能单独推导上传许可；完成的历史交付授权不自动涵盖后来新增内容。

核对实际 push URL（含额外 pushurl、URL 重写等）、账号/组织、仓库和目标 ref；若存在多个推送目标，必须全部在授权范围内，否则暂停相关推送。不要将凭据嵌入 URL 或输出认证秘密。

了解推送是否触发部署、发布或其他外部动作；授权不能静默扩大到这些动作。用明确目标和 ref 范围推送，不默认 `--all`、`--mirror` 或批量标签。

先 fetch 实际授权目标并检查其分支关系：

- 目标不存在：仅在允许新建该分支时推送。
- 目标与本地相同：无需重复推送。
- 目标是本地祖先：可按策略正常推进。
- 目标领先或分叉：停止自动 push，不自动 pull/rebase/merge；若用户已明确分配集成任务，则在该范围内处理并重新验证。
- fetch 失败：不能声称核实了远端状态；保留本地提交并说明。

禁止未获当前操作明确授权的强推（包括 `--force-with-lease`、带 `+` 的强制 refspec）、远端删除和历史重写。检查后发生竞争导致拒绝时重新核对，不能通过强推“修复”。

push 后确认实际目标结果，再报告已同步。需要 CI 或合并才能完成的任务继续按其完成标准检查，不将“已推送”等同于“已合并/已部署/CI 通过”。

## 分支、并行与离线

分支名沿用现有约定；本项目需要新任务分支时采用 `codex/<task-id>-<slug>`，不绑定 Agent 身份。不要重命名用户已有分支。

按需使用 worktree，不能假设它自动带入原工作区的未提交修改；分支隔离也不隔离共享数据库等外部资源。共享 Git 设置、集成与清理协调执行。`git worktree lock` 不是工作区写入互斥锁。

无远端或网络失败时，本地提交仍是有效本地 checkpoint；跨电脑恢复需要额外的可取得副本。删除分支/worktree 前需确认授权及未提交、未推送、被忽略的重要内容已妥善保留，不自动清理未知工作。
