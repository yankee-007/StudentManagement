# ADR-012：可跟进状态独立于反馈状态

## Status
Accepted。2026-10-07用户要求独立字段，并确认已回应可填是；后续明确增加未填写空状态，保留第9/16批标记，其余批次为空。

## Context
反馈非空仅表示有记录，未接听电话也可能有记录。文字不统一，不能持续自动推断补课意愿。此前反馈状态判定修复已按用户要求回退。

## Options Considered
- 按反馈kind统计：误把联系尝试算作可跟进。
- 保存时解析文字：与用户要求人工填写不符。
- 独立批次人工标记（采用）。

## Decision
业务状态为未填写（空值）/是/否。campaign_followup_status以批次/学员为主键，仅保存是/否；缺行表示未填写，选择未填写删除标记记录，不需重建原表约束。表格与导出为空，详情选择器显示未填写；新批次默认空。手工标记不会被反馈保存、学习刷新或新建批次覆写；新批次不继承旧值。真实学员可通过详情选择修改，按班级/批次/学员捕获身份校验。历史可补充此独立标记，历史学习/反馈仍只读。

正式看板按恰好完成k节分桶计在读非补位且标记是者；独立学习概览按用户最新澄清统一为全班在读非补位，人数为恰好N节、可跟进为其中是标记者，不累加低次数；未填写与明确否保持区分。整批未标记人数为—，明确全否为0，覆盖另外提示。均不再用反馈状态判定。导出、字段管理和筛选包含新字段。正式概览读取兼容与独立选择见ADR-013。

## Rationale
联系记录与是否继续跟进是不同的人工判断，独立保存才能允许修正而不改原反馈。

## Consequences
第9/16次按用户授权人工审阅反馈填写，保留现有是/否判断；规则不作为长期自动分类器。用户明确其余批次为空，执行一次性清理而非启动时自动清理；后续人工填写其他批次仍允许保存。写前SQLite备份，核对原表与保留批次标记不变；真实数据/备份不入Git。
