# ADR-003: 群发参数自动保存与显式发送边界

## Status

Accepted。2026-09-29 根据当时的交互调整整理；2026-10-09按用户聊天气泡需求替换统一配置行布局，自动保存与显式发送边界沿用；同日补充「重命名只改名单标题、不属于内容或参数变化」，对调群发名单与发送配置，并新增可切换的逐人消息列表。

## Context

用户反馈消息编辑、批量修改和预览发送不顺手，明确要求参数移到左侧，删除保存设置/撤销修改按钮，自动保存，只保留设置标题旁一个“预览并发送”入口。

## Options Considered

本 Session 先存在显式保存/撤销和额外预览入口，随后用户要求改为自动保存及单入口。没有关于其他自动发送方案的可靠讨论记录。

## Decision

发送配置常驻群发名单右侧，主界面按群发名单／纵向聊天模板／发送配置三栏排列（消息模板居中），姓名前缀在列表上方。前缀/参数仍600ms防抖保存；输入框 Enter 加入一条文字，Shift＋Enter 在消息内换行，组合输入确认不加入。附件独立成条，气泡支持双击编辑、回车或点击外部提交、Esc 取消、删除与排序，移除内联保存/取消栏。每次已提交的气泡操作采用现有整稿事务自动保存；“发送”仅加入模板。后端以list_id与内容修订拒绝陈旧草稿，事务失败保留旧内容与当前编辑稿，取消该编辑不会把失败新值带入后续保存。预览、名单/模块切换及关闭前提交有效内联编辑；空白或失败稿阻止操作，待加入文字须显式加入或清空。已保存内容/参数变化清空预览确认，预览窗口显式开始才启动队列。关闭粘贴后回车发送时，单条发送选项置灰且发送器不执行消息回车；默认粘贴等待改为 0.5 秒，已有名单显式保存的参数保留。名单标题与内容是两回事：顶部工具条的「重命名」只改 lists.title，不改人员、消息或发送参数，因此不触发这里的预览失效；只有人员、消息或发送参数真正变化时才清空预览确认。手填或粘贴加入姓名、删除待处理姓名都属于人员变化，必须清空预览确认；新建群发方案只收名称（成员与消息随后补），空方案先存模板不改变任何人的消息。

公共消息默认通过常驻聊天模板编辑；标题右侧可切换为逐人消息列表，保留标题和说明。列表和姓名共用当前待处理／已发送模型，采用相同 40px 行高、表头／视口／页脚尺寸，按 contentY−originY 双向联动，长消息独立横向查看。与左侧页签等高对齐的「统一配置消息模板」单元格打开弹窗，复用原聊天编辑器实例；切换查看方式先检查模板草稿。列表显示个人实际有序文字／附件，姓名或消息双击打开同样的个人聊天编辑器，显式保存仅作用于该人。模板修改默认保留个人改动；覆盖个人改动需在“更多”明确确认，未改的混合槽位保持各自内容。删除公共槽位也删除对应个人改动，界面提示；受保护发送状态不可覆盖。待核实结果的核实动作移入个人窗口。预览按人员显示有序文字/文件，可返回编辑。

## Rationale

降低重复操作，同时保留“保存配置”和“执行发送”的明确边界。自动保存不意味着旧预览仍代表当前内容。

## Consequences

新增参数、编辑或名单切换路径都必须检查保存归属与预览失效。保留发送前/每人开始的验证，以及文件变更检查、F11、尝试持久化与不确定结果保护。不可为简化交互而把参数保存连到 start。

## Rejected / Failed Approaches

显式保存/撤销按钮和重复预览入口是被用户替换的交互，不是无效业务数据。没有证据表明本次发生过真实误发；自动测试只使用模拟驱动。
