# ADR-003: 群发参数自动保存与显式发送边界

## Status

Accepted。2026-09-29 根据当时的交互调整整理；2026-10-09按用户聊天气泡需求替换统一配置行布局，自动保存与显式发送边界沿用；同日补充「重命名只改名单标题、不属于内容或参数变化」，对调群发名单与发送配置，并新增可切换的逐人消息查看；随后按用户反馈改为字段分列表格、固定切换几何并补充文件粘贴／拖放。

## Context

用户反馈消息编辑、批量修改和预览发送不顺手，明确要求参数移到左侧，删除保存设置/撤销修改按钮，自动保存，只保留设置标题旁一个“预览并发送”入口。

## Options Considered

本 Session 先存在显式保存/撤销和额外预览入口，随后用户要求改为自动保存及单入口。没有关于其他自动发送方案的可靠讨论记录。

## Decision

发送配置常驻群发名单右侧，主界面按群发名单／纵向聊天模板／发送配置三栏排列（消息模板居中），姓名前缀在列表上方。前缀/参数仍600ms防抖保存；输入框 Enter 加入一条文字，Shift＋Enter 在消息内换行，组合输入确认不加入。附件独立成条，气泡支持双击编辑、回车或点击外部提交、Esc 取消、删除与排序，移除内联保存/取消栏。每次已提交的气泡操作采用现有整稿事务自动保存；“发送”仅加入模板。后端以list_id与内容修订拒绝陈旧草稿，事务失败保留旧内容与当前编辑稿，取消该编辑不会把失败新值带入后续保存。预览、名单/模块切换及关闭前提交有效内联编辑；直接提交空白或失败稿阻止操作；空白内联稿点击外部或失焦等同 Esc 取消并保留原文，待加入文字须显式加入或清空。已保存内容/参数变化清空预览确认，预览窗口显式开始才启动队列。关闭粘贴后回车发送时，单条发送选项置灰且发送器不执行消息回车；默认粘贴等待改为 0.5 秒，已有名单显式保存的参数保留。名单标题与内容是两回事：方案下拉框右键菜单的「重命名」只改 lists.title，不改人员、消息或发送参数，因此不触发这里的预览失效；只有人员、消息或发送参数真正变化时才清空预览确认。手填或粘贴加入姓名、删除待处理姓名都属于人员变化，必须清空预览确认；新建群发方案只收名称（成员与消息随后补），空方案先存模板不改变任何人的消息。

公共消息默认通过常驻聊天模板编辑；标题右侧可切换为逐人字段表格，保留标题和说明，两种模式使用相同布局尺寸。消息1／消息2…作为列标题，正文不附加标号或拼接分隔符；表头随字段横向移动，消息与姓名采用同源待处理／已发送顺序及 recordKey、40px 行高和等高视口，按 contentY−originY 双向联动。单元格长文省略，悬停在只读浮层中滚动查看；点击字段表头在弹窗复用原聊天编辑器实例，切换查看方式先检查草稿。气泡操作仅悬停或键盘聚焦时显示，保留工具行占位避免跳动。输入框粘贴或拖入本地文件作为附件，整批验证成功后沿用原提交／失败保护，文字稿保留，普通文字粘贴沿用原输入，拖放只复制文件。姓名或消息双击打开同样的个人聊天编辑器，显式保存仅作用于该人；Esc 取消整个弹窗的未保存修改。消息 personal_override 同时驱动姓名旁「已单独编辑」和表格对应消息提示，模型更新后即时刷新，显式套用模板后清除。方案下拉框收起／展开项均可右键重命名或删除，目标身份独立于当前选择；右键保留已展开列表，重命名在目标行内编辑，回车保存、Esc 取消，关闭列表取消未保存名称，失败保留输入并提示；删除需确认，事务清除该方案的本地名单、消息和发送记录，发送中、待核实或来源回写未完成时拒绝删除，来源库不变。模板修改默认保留个人改动；覆盖个人改动需在“更多”明确确认，未改的混合槽位保持各自内容。删除公共槽位也删除对应个人改动，界面提示；受保护发送状态不可覆盖。待核实结果的核实动作移入个人窗口。预览按人员显示有序文字/文件，可返回编辑。

2026-10-10 按用户要求新增「剪贴板模式」。消息来源随当前名单自动保存，模式变化清空预览；切换前沿用有效内联编辑与待加入输入检查。剪贴板模式不要求模板/个人消息，预览时捕获本轮快照并展示类型/文字/文件摘要，发送器在搜索联系人后恢复同一份内容，每人仅粘贴一次、按 confirm_send 可选回车，single_send 不生效。模板/个人消息不被覆盖，变量原样发送；快照只在内存，重启/更换内容需重新复制预览。原显式开始、启动/逐人复核、文件变化、F11和待核实保护仍适用；真实客户端图片/富文本表现不能由模拟测试代替。

## Rationale

降低重复操作，同时保留“保存配置”和“执行发送”的明确边界。自动保存不意味着旧预览仍代表当前内容。

## Consequences

新增参数、编辑或名单切换路径都必须检查保存归属与预览失效。保留发送前/每人开始的验证，以及文件变更检查、F11、尝试持久化与不确定结果保护。不可为简化交互而把参数保存连到 start。

## Rejected / Failed Approaches

显式保存/撤销按钮和重复预览入口是被用户替换的交互，不是无效业务数据。没有证据表明本次发生过真实误发；自动测试只使用模拟驱动。
