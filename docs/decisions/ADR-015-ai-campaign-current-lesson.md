# ADR-015：AI 催交按当前课程节次选模板，结果写独立名单

## Status

Accepted。2026-10-09，依据本任务用户明确选择：课程节次自动选择且可手选；失败留空、名单照常创建，可补写或重试。

## Context

用户提供32份催交素材，文件名及AA说明使用“催交次数”；应用需要在当前筛选名单生成自然话术。用户已取消反馈记忆和状态机，最终明确按当前课程节次选模板。生成过程异步，名单／数据及个人消息可能变化。

## Options Considered

- 按学员参与的催办批次轮次自动选择：本轮确认选择课程节次。
- 只有全部成功才创建名单：用户选择失败者留空，名单照常创建。
- 反馈记忆／状态机：用户明确排除，不实现。

## Decision

当前节次取本批快照 dashboard.opened；第N节用第N份，超过32取第32份，无有效节次须手选。素材只读，素材中的次数语义不能覆盖这一用户选择。只依据当前快照已知欠课／欠作业生成，不从未知值推断未完成。

生成／重试请求在工作线程执行；名单与欠账在开始时冻结，创建时再次核对。学号作为JSON key，集合必须一致，欠课／欠作业分别校验，失败自动退避重试且保留成功项。API Key只入keyring，不入SQLite或任务记录；服务配置只保存非密参数。实际生成由用户点击触发，界面说明会向服务发送哪些学员数据。

结果作为既有recipients.content保存，成功项标为个人内容；失败留空并在既有learning_data存诊断、模板索引和错误供恢复重试，不新增表或发送状态。重试只填仍为空且有失败标记、无受保护发送记录的人员；期间手写内容优先。创建名单后仍需预览与显式启动。

## Rationale

课程节次是本轮明确的业务口径；模板文件名不能导致后续实现又改回次数。生成结果独立于学习／反馈／发送事实，避免引入新的状态机或错误回写。身份复核与个人内容保护避免异步结果落入新班期或覆盖编辑。

## Consequences

本地32次催交话术库是只读运行依赖，目前未纳入本任务提交，移机必须另行携带。真实模型的JSON支持、参数兼容性、额度和主观效果需实际服务验收；自动测试只用mock，不能报告真实AI调用成功。空消息由既有群发预览阻止；生成不会自动发送。
