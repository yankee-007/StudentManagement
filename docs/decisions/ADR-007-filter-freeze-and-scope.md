# ADR-007: 筛选结果为冻结集合，业务范围只算真正匹配的行

## Status

Accepted。2026-09-30 由用户明确确认三点后实施：整集冻结；重新筛选清单按“值变化不重算、显式改变视图才重算、排序只重排不重判”；名单生成/导出/批量未回复只算真正匹配的人。

## Context

画像表格与催办工作台的“按选项”筛选是显示层派生视图：每次数据变动（单元格自动保存、记录反馈、草稿、免催日期、备注、发送状态回写）都会重跑 `_matches_filters` 并重建模型。结果是把某学员的字段改到不再符合当前条件时，这一行会立刻从表格里消失，而右侧仍在编辑他；工作台在“待反馈”视图登记反馈后同样当场掉行并自动推进选择。用户要求 Excel AutoFilter 式语义：应用筛选后结果集固定，条目被修改也仍然显示，只有清除筛选或重新筛选时才更新。

## Options Considered

1. 只冻结“当前操作的那一行”（改动最小，但连续处理多人时前几行仍会消失）。
2. 整集冻结 + 业务范围继续只算真正匹配的行（本决定）。
3. 整集冻结并把可见集合直接当作业务范围：被否决——会让名单生成、导出画像、批量未回复静默包含已不符合条件的人，破坏 ADR-001 的“独立名单就是当前筛选人员”。

## Decision

- 两个模块各自维护 `_frozen`（本次应用筛选时命中的 record_key/student_id 集合）。存在查询条件（列筛选、搜索、非“全班快照”视图）时才冻结；没有条件时保持实时视图，新导入的学员照常出现。
- 渲染集合 = `_rows` 中仍属于 `_frozen` 的行；渲染时逐行写入 `_filter_stale` 标记（该行当前已不满足筛选条件），由 DictTableModel 的 `staleRow` 角色交给 QML 淡色显示。
- **值变化不重算**：单元格自动保存、记录反馈、草稿、免催日期（含浮窗与工作台按钮）、备注、发送状态回写都只更新行数据与过期标记，不重新判定、不切换正在编辑的学员。
- **显式改变视图才重算**：搜索、视图切换、列筛选确定/重置/清除、切班、切批、画像「刷新」/工作台「刷新数据」、名单同步、导入画像名单。**切换模块不算重新筛选**：Main.qml 的 switchModule 调用 ProfileModule.activate()/Workflow.activate()，只重读数据（refresh/refresh_live 传 keep_query=True），处理中的名单不因切页面而改变。列集合变化（隐藏/删除列）会裁剪筛选条件，属于条件变化，此时强制重算。
- **排序只重排不重判**：点表头排序使用冻结集重新排序，不重新求值，避免排序顺手把筛选刷新掉。
- **业务范围 = 渲染集合去掉过期行**：ProfileModule/Workflow 的 `recipientKeys`、画像导出、工作台「批量未回复」都按这个范围取人。`tableModel.rows` 仍是“看得见的行”，不得直接当作业务范围。
- 界面必须暴露状态：计数写成“显示 N 人（其中 K 人已不符合当前筛选）”，提供「重新应用筛选」入口；过期行淡琥珀底色 + 告警色文字；工具条显示游标“正在处理 第 i / n 条 · 姓名”。
- **选择必须连续**：重新筛选后若原选中行已被筛掉，新选择 = 原顺序中它之后的第一个仍在列表里的人（下一条），再退到它之前的最后一个人，最后才回到第一行；不得回落到 rows[0]。实现为 app/table_query.py 的 next_cursor，画像与工作台共用。工作台登记反馈后仍按原行为推进到下一位。

## Rationale

编辑过程中的列表应当稳定，用户才能连续处理同一批人；但“看得见的行”一旦等于“要发的人”，就会静默扩大群发范围。把“判定”与“渲染”拆开后，冻结只影响显示，业务范围仍由实时匹配决定，两个需求同时满足。

冻结只保证“行不掉”，不保证“人找得到”：一旦用户主动重新筛选，已处理的行会被移除，若选择回落到 rows[0]，界面等于把人打回队首，会重复处理已完成的学员。因此冻结与选择连续性必须同时实现——前者保证处理中不被打断，后者保证重新筛选后仍能立刻知道下一条是谁。

## Consequences

- `_model.rows` 的语义从“当前搜索/筛选/排序集合”变为“当前显示的冻结集合（可能含过期行）”；新增匹配集概念后，任何新的业务取数必须走 `_scope_rows()`（渲染集合去掉过期行），不能直接读 `_model.rows`。
- 空态与计数需要区分“匹配 0 人”和“显示的全是过期行”，否则用户会看到一张全是过期行的表。
- 冻结行在切班、切批、学员被名单同步移除时自动丢弃（键不在 `_rows` 中即不渲染）。
- 用户会更容易停在过期视图里；「重新应用筛选」按钮与计数提示是这套语义的必要组成，不得省略。
- 免催日期、发送结果等原本通过 `refresh()`/`reload_rows()` 全量重建的路径需要显式传 `keep_query=True`，默认仍为重算（保持与今日行为一致，未传的调用点不会静默变成冻结）。

## Rejected / Failed Approaches

- 只冻结当前行（选项 1）：未满足“整集冻结”的确认结果，未采用。
- 把 `_model.rows` 直接当业务范围：会改变群发名单与导出范围，未采用。
- 编辑后直接清空筛选或整表重排以“让行回来”：等于放弃筛选，未采用。
