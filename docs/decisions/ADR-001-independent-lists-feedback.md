# ADR-001: 筛选名单与反馈独立于发送

## Status

Accepted。2026-09-29 根据本 Session 用户确认及当前代码整理。

## Context

用户将催办工作台定位为生成名单、登记反馈的入口，要求不再显示发送相关内容，名单生成参考学员画像，并明确同时提供“配置消息生成”和“仅生成人员名单”。用户也确认批量未回复只处理当前筛选可见人员，非空内容不能覆盖。

## Options Considered

- 旧实现按发送状态限制反馈/批量未回复，生成与来源批次关联的催办发送计划。
- 本轮明确采用画像式筛选名单；消息配置与仅人员名单两种方式都提供。其他备选方案缺少可靠记录，不补写。

## Decision

当前入口按筛选/排序后的真实有姓名人员生成独立名单，不额外套用催办资格。生成期间校验捕获的 recipientKeys。工作台限最新批次生成，人员名单允许空消息，模板模式发送前必须补齐。2026-10-10 用户新增剪贴板模式：使用预览时固定的统一剪贴板内容，可直接处理空消息名单；独立名单、反馈与旧来源保护语义沿用。

反馈登记与发送成功脱钩。批量未回复只在本次催办/待反馈可用，后端也检查视图并传入可见学号；任何反馈记录或非空草稿都跳过。

保留旧来源名单的发送资格复核、结果回写及防重试机制，不迁移已有名单的语义。

## Rationale

落实用户明确选择，使工作台范围与看到的人员一致，并让实际聊天反馈不受旧发送状态限制；已有持久化名单仍需按原语义安全恢复。

## Consequences

独立名单重复生成是新任务，不能承诺跨名单防重复发送；全班视图生成也不会自动排除免催者。旧来源名单仍可能在源批次变历史后被阻止。不要把两条路径统一成一个资格条件。导出全班与生成筛选名单的范围不同。

## Rejected / Failed Approaches

旧发送依赖规则已被当前入口替代，但不表示旧路径代码完全废弃。实现回归中，旧测试仍期待未发送/不确定结果不能标记未回复；这些期望根据明确的新规则更新，发送恢复保护测试继续保留。无证据表明还尝试过其他设计。
